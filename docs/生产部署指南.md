# AgentMonitor 生产部署指南

本文档描述 AgentMonitor（可观测 + 评测平台）在生产环境的部署、配置与运维。包含 Docker Compose 一键部署、环境变量、数据库迁移、Service Token、Webhook 告警、备份与故障排查。

## 1. 架构与组件

| 组件 | 端口（容器内） | 说明 |
|---|---|---|
| frontend | 80/443（Nginx 静态资源 + API 反代） | React SPA |
| backend | 3000（Fastify Node 服务） | API、评测 Worker、定时调度、采样回流、告警评估 |
| postgres | 5432 | 持久化（SQLite 仅用于本地开发，生产必须 PostgreSQL） |

backend 进程内嵌 Evaluation Worker，负责：RunItem 领取/执行（500ms 轮询）、过期租约回收（10s）、Scheduled Run 到期扫描（30s）、Trace Sampling 回流扫描（60s）。生产可通过多副本横向扩展——所有领取动作均为原子 SQL（条件 UPDATE / claim），多副本不会重复处理；但 **同一时间建议 ≤ 2 个 backend 副本**，避免 SQLite 误配置（生产必须为 Postgres）。

## 2. 环境变量

在项目根目录创建 `.env`（docker-compose 通过 `env_file` 注入）：

```bash
# ---- 数据库（PostgreSQL 必须）----
DB_TYPE=postgres
PG_HOST=postgres
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=请修改为强密码
PG_DATABASE=agentmonitor
# 可选：直接使用连接串（优先于上面分项）
# DATABASE_URL=postgres://user:pass@host:5432/agentmonitor?sslmode=require
PG_POOL_MAX=10
PG_SSL=false

# ---- 安全（生产必须修改）----
JWT_SECRET=请使用 openssl rand -hex 32 生成的随机串
CORS_ORIGINS=https://your-console-domain.example.com

# ---- 运行模式 ----
NODE_ENV=production
PORT=3000
```

> ⚠️ `JWT_SECRET` 必须在所有副本间保持一致；轮换密钥会使已签发的 JWT 失效（用户需重新登录），Service Token 不受影响（使用独立 hash）。

## 3. 部署步骤（Docker Compose）

```bash
# 1. 准备配置（生产建议使用 .env.production.example 模板）
cp .env.production.example .env   # 或 cp .env.example .env
vim .env                          # 修改 PG_PASSWORD / JWT_SECRET / CORS_ORIGINS

# 2. 生成自签证书（无域名 / 按 IP 访问场景，详见 4.1 节）
bash scripts/ssl-setup.sh --self-signed
#   如有公网 IP，追加：--ip <公网IP>（脚本会自动探测本机局域网 IP 写入证书 SAN）

# 3. 构建并启动
docker compose build
docker compose up -d

# 4. 查看健康状态（backend 暴露 /health）
docker compose ps
curl -kf https://localhost/api/health || curl -f http://localhost:3000/health

# 5. 查看日志
docker compose logs -f backend
```

> 必填变量强校验：`PG_PASSWORD` 与 `JWT_SECRET` 未设置时 `docker compose config/up` 会直接报错，
> 避免弱密码/弱密钥上线。容器内连接自带 PostgreSQL 已固定 `DB_SSL=false`（内网无 TLS）。

数据库表结构在服务启动时**自动迁移**（迁移台账 `schema_migrations` 保证幂等，当前 p001~p015）。升级镜像后重启 backend 即自动应用新迁移，无需手动执行 SQL。

### 3.1 systemd 直部署（无 Docker）

仓库根目录提供 `agentmonitor-backend.service` 与 `agentmonitor-frontend.service` 模板，以及 `deploy.sh` 脚本：

```bash
# backend：Node 20+
cd backend && npm ci && npm run build
# 通过环境变量或 .env 配置 DB_TYPE=postgres 等
sudo cp ../agentmonitor-backend.service /etc/systemd/system/
sudo systemctl enable --now agentmonitor-backend

# frontend：构建静态资源后由 Nginx 托管
cd ../frontend && npm ci && npm run build
```

## 4. 反向代理与 HTTPS

frontend 容器内置 Nginx，把 `/api`、`/api/v2`、`/ws` 反代到 backend。生产建议：

- 在 `./ssl/` 放置 `fullchain.pem` 与 `privkey.pem`（compose 已挂载到 `/etc/nginx/ssl`），或在前置 LB（ALB/SLB/Cloudflare）终止 TLS。
- WebSocket（`/ws`，实时 Trace 推送）需要在反代层开启 `Upgrade` / `Connection` 头透传并放宽读超时（建议 60s+）。
- 健康检查路径：`GET /health`（无需鉴权）。

### 4.1 无域名 + 自签证书 + IP 访问

当没有域名、直接通过服务器 IP 访问时，使用仓库自带的自签证书脚本：

```bash
# 自动探测本机局域网 IP 并写入证书 SAN，同时包含 127.0.0.1 / localhost
bash scripts/ssl-setup.sh --self-signed

# 若服务器还有公网 IP，务必一并追加（可多次 --ip），否则浏览器按公网 IP 访问会报证书不匹配
bash scripts/ssl-setup.sh --self-signed --ip 203.0.113.5
```

- 脚本在 `./ssl/` 生成 `cert.pem`、`key.pem`（compose 已挂载到前端容器 `/etc/nginx/ssl`）与 `openssl-san.cnf`。
- 证书默认有效期 825 天；SAN 会包含所有探测/指定的 IP，`https://<IP>/` 访问时在浏览器手动信任一次自签证书即可。
- `.env` 的 `CORS_ORIGINS` 必须与实际访问地址一致，例如 `https://203.0.113.5`（https + IP，不要填 http 或 localhost）。
- 前端 Nginx 已配置 80→443 跳转、`/api`、`/ws`（含 WebSocket Upgrade）反代到 backend。
- 自签证书仅适用于内网/演示/自用场景；对公网用户提供服务时，建议后续接入域名并改用 Let's Encrypt（`bash scripts/ssl-setup.sh --domain <域名>`）或在前置 LB 终止 TLS。

## 5. 初始化与接入

1. 浏览器访问控制台，注册首个账号（该账号自动成为第一个项目的所有者）。
2. **SDK 接入（Telemetry）**：在项目设置创建 API Key（V1，`sk_`/旧格式）或 Service Token（V2，`amt_` 前缀）。
   - Service Token 支持最小权限 scope：`telemetry:write`（上报）、`prompts:read`（Runtime 拉取 Prompt）、`evaluation:run`（触发/执行评测）、`evaluation:result:write`（External Runner 回传）等。
   - SDK 三语言（TypeScript / Python / Go）通过 `AGENTMONITOR_TOKEN` 或 apiKey 配置。
3. **Prompt Runtime**：Agent 通过 `GET /api/v2/runtime/prompts/:name?environment=production` 拉取已发布 Prompt，支持 ETag/304 缓存；A/B 实验传 `bucketKey`（用户/会话 ID）。
4. **CLI / External Runner**：`npx agentmonitor eval run --wait --gate --min-pass-rate 0.8` 接入 CI；内网 Agent 用 `agentmonitor runner <runId> --command <cmd>` 本地执行。

## 6. 自动化能力运维要点

| 能力 | 触发周期 | 运维检查点 |
|---|---|---|
| Scheduled Run（定时回归） | Worker 30s 扫描 | `scheduled_runs.next_run_at`、`last_status`；`last_status=failed` 时检查 Experiment 是否通过 validate |
| Trace Sampling（采样回流） | Worker 60s 扫描 | `sampling_rules.sampled_count/matched_count`、`last_scanned_at`；回流目标 Dataset 的 item_count |
| Alert Rule（告警） | Run 终态实时评估 | `alert_events.delivery_status`；Webhook 失败显示 `failed` 与 `delivery_error`，修复后可重新触发 |
| Prompt A/B | Runtime 请求时分桶 | `prompt_ab_variants.weight`；同一 bucketKey 稳定命中同一变体（确定性 hash） |

### 6.1 Webhook 告警

- 在控制台「评测 → 告警规则」配置 Webhook URL（飞书/Slack/钉钉机器人均可，接收标准 JSON POST）。
- 平台对 Webhook 做 5s 超时、非 2xx 判失败；失败事件保留在 `alert_events`（`delivery_status=failed`），不会静默丢失。
- 同一 Run 同一规则通过指纹去重（UNIQUE(rule_id, fingerprint)），并受 `cooldown_minutes` 冷却窗口约束。

飞书机器人示例（Webhook URL 直接填 `https://open.feishu.cn/open-apis/bot/v2/hook/<token>`，平台 POST JSON 中含 `title`/`message` 字段；如需飞书卡片格式，建议在中间加一层转换网关）。

## 7. 备份与恢复

PostgreSQL 逻辑备份即可（无本地文件状态；SQLite 的 `data/` 目录仅本地开发使用）：

```bash
# 备份
docker compose exec postgres pg_dump -U postgres agentmonitor > backup_$(date +%F).sql

# 恢复
cat backup_2026-08-27.sql | docker compose exec -T postgres psql -U postgres agentmonitor
```

建议：每日全量 + WAL 归档（生产 RDS 开启自动备份）。迁移台账 `schema_migrations` 会随备份一同保存，恢复后无需重新迁移。

## 8. 监控与故障排查

- **健康检查**：`/health` 返回 200；`/api/v2/...` 鉴权失败返回 401/403。
- **日志**：backend 使用 pino JSON 日志；关注 `[evaluation-worker]`、`[alert-rule]`、`[trace-sampling]`、`[scheduled-run]` 前缀。
- **常见问题**：
  - Run 一直 queued：检查 backend Worker 是否启动（日志含 `[evaluation-worker] started workerId=`）；多副本时钟需同步（NTP）。
  - Webhook 收不到：查 `alert_events.delivery_error`（ECONNREFUSED/超时/HTTP 非 2xx）；确认出站网络策略。
  - Runtime 返回 404：Prompt 未发布到对应环境（`prompt_deployments` 无记录）；A/B 变体未命中时回落基线指针。
  - 采样不回流：确认规则 enabled、Dataset 同项目、Trace 有 input；未命中采样率也会登记台账（`sampled_traces.dataset_item_id` 为空）。
